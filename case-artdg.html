사례: artdg.com 이관·재구축

1. 이관과 구조

옛 사이트의 상품 데이터를 새 구조로 옮기고, 방문자가 상품을 찾고 수량을 계산해 장바구니에 담을 수 있게 하는 것이 범위였습니다. 상품 데이터는 옛 사이트 DB에서 가져왔습니다.

상품 135개, 안내 페이지 5개, 묶음 할인 규칙 2종, 상품정보 응답 52~170ms입니다.

2. 관리자와 안전장치

운영자는 코드를 고치지 않고 관리자에서 값을 바꿉니다. 설정 변경은 초안을 거쳐 발행해야 사용자 화면에 반영되고, 발행 이력이 남습니다.

관리자 화면 범위

상품·옵션, 카테고리, 판매 기준, 구매 규칙, 묶음 할인, 배송, 안내·법적 표기, 사업자 정보, 페이지·리다이렉트, 발행, 연결 점검.

이 목록은 코드 기준으로 확인한 것입니다. 목록 중 아래 화면 6종 외에는 운영 화면을 직접 눌러 확인한 것이 아닙니다.

관리자 둘러보기 영상

관리자를 한 바퀴 둘러보는 약 1분 영상은 제안 시 비공개 링크로 전달합니다.

3. 주문과 네이버페이

네이버페이는 연동 중(sandbox 검수 단계)입니다. 실결제 운영 단계가 아닙니다. 구매 버튼에서 주문서 화면으로 이어지는 흐름을 검수용 환경에서 확인하는 단계이고, 실제 결제 완료는 확인하지 않았습니다.

아직 없는 기능

  • 취소·반품·교환, 주문 상태 동기화는 아직 만들지 않았습니다.
  • 자체 로그인, 회원, 자체 결제 화면, 주문내역은 만들지 않았습니다.

고객 프로젝트에서 이 기능이 필요하면 새로 개발하는 범위로 따로 견적합니다.

4. 납품 방식

소스와 디자인의 재사용 권리를 보유하고 있습니다. 고객에게 소스 전체 소유권을 넘기는 계약인지는 건마다 따로 정합니다.

  • 기능별 완료 기준을 착수 전에 문서로 정하고, 1~2주 단위로 검수합니다.
  • 테스트·배포·관리자 매뉴얼을 함께 인도합니다.
  • 소스 인수인계 범위와 무상 하자보수 범위를 계약서에 명시합니다.

공개하지 않는 것

저장소는 비공개입니다. 이 페이지에는 커밋 수, 활동일, 구조 요약과 화면 캡처만 실었고 코드, 주문·운영 데이터는 싣지 않았습니다. 화면은 주문자 정보가 없는 것만 골랐습니다.
