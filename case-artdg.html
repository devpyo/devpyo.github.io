사례 상세: artdg.com 이관·재구축

운영 중인 종이·미술 재료 쇼핑몰 카탈로그입니다. 옛 그누보드/영카트 사이트를 Next.js 정적 사이트로 옮기고, 관리자에서 값을 바꿔 발행하는 구조로 다시 만들었습니다.

artdg.com 열기

성격
이관·재구축 (처음부터 만든 사이트가 아닙니다)
공개 사례
이 1건입니다. 여러 고객사 납품 실적이 아닙니다.
기간
커밋 288개, 활동일 8일

1. 문제와 범위

옛 사이트의 상품 데이터를 새 구조로 옮기고, 방문자가 상품을 찾고 수량을 계산해 장바구니에 담을 수 있게 하는 것이 범위였습니다. 운영자는 코드를 고치지 않고 관리자에서 값을 바꿉니다.

  • 135개상품
  • 5개안내 페이지
  • 2종묶음 할인 규칙
  • 52~170ms상품정보 응답

상품 데이터는 옛 사이트 DB에서 가져왔습니다.

2. 구조

  • 사용자 화면: Next.js 정적 사이트. 카탈로그, 검색, 분류, 규격·가격·묶음 단위 표시, 수량 계산, 장바구니.
  • 실행 환경: Cloudflare Workers와 D1 위에서 동작합니다.
  • 관리자: 접근 제한이 걸린 별도 경로에서 상품·설정·사이트 콘텐츠를 스키마 기반으로 편집하고 발행합니다.
  • 품질: 자동 테스트, E2E 테스트, 배포 가드, 운영 문서(RUNBOOK)가 있습니다.

관리자 화면 범위

상품·옵션, 카테고리, 판매 기준, 구매 규칙, 묶음 할인, 배송, 안내·법적 표기, 사업자 정보, 페이지·리다이렉트, 발행, 연결 점검, 에이전트 권한.

관리자 안전장치

  • 가격 인하 1회 25% 이내, 원본가 50% 미만 불가
  • 변경 감사 기록, 버전 충돌 방지
  • 설정 변경은 초안을 거쳐 발행해야 반영

3. 결제·주문 상태

네이버페이: 연동 중(sandbox 검수 단계)입니다. 실결제 운영 단계가 아닙니다.

구매 버튼에서 주문서 화면으로 이어지는 흐름을 검수용 환경에서 확인하는 단계입니다. 실제 결제 완료는 확인하지 않았습니다.

아직 없는 기능

  • 취소·반품·교환, 주문 상태 동기화는 아직 만들지 않았습니다.
  • 자체 로그인, 회원, 자체 결제 화면, 주문내역은 만들지 않았습니다.

고객 프로젝트에서 이 기능이 필요하면 새로 개발하는 범위로 따로 견적합니다.

4. 다른 프로젝트에서 다시 쓰는 범위

소스와 디자인의 재사용 권리를 보유하고 있습니다. 고객에게 소스 전체 소유권을 넘기는 계약인지는 건마다 따로 정합니다.

재사용 범위
기존 시스템으로 되는 것고객별로 새로 개발할 것
  • 상품 카탈로그, 검색, 분류
  • 규격·가격·묶음 단위 표시
  • 수량 계산과 장바구니
  • 관리자 화면과 발행 절차
  • 변경 감사 기록, 버전 충돌 방지
  • Cloudflare Workers/D1 배포, 자동 테스트·E2E·배포 가드
  • 고객 도메인의 상품 데이터 모델 이관
  • 디자인 적용
  • 고객사 결제수단 연동
  • 견적·주문 워크플로
  • 취소·반품·상태 동기화
  • 회원·로그인

5. 공개하지 않는 것

저장소는 비공개입니다. 이 페이지에는 커밋 수, 활동일, 구조 요약만 적었고 코드, 관리자 화면 이미지, 주문·운영 데이터는 싣지 않았습니다. 3분 관리자 데모 영상은 제안 시 비공개 링크로 전달합니다.
